AI Agent 아키텍처 — LLM 호출 · 도구 연동 · 결과 처리

반도체 플라즈마 식각 공정 이상탐지 시스템 · 에이전트 계층

현재 구현은 LLM이 도구를 자율 선택하는 구조가 아니다. 오케스트레이터(server.py)가 SHAP 분석과 Knowledge Graph 조회를 먼저 실행하고, 그 결과를 컨텍스트로 묶어 LLM을 호출한다. LLM이 추가 정보를 요청해 도구를 다시 부르는 경로는 없다.

1. 실행 흐름

진입 경로는 둘이다. 실시간 경로는 Kafka 세 토픽(OES · MACHINE · RFM)을 (설비, run, time_step) 키로 병합해 추론 엔진에 넣고, 오토인코더 재구성 오차와 LightGBM 분류로 이상을 판정한다. 이상이면 백그라운드 태스크로 ②부터 실행된다. 수동 경로는 정비 담당자가 React 탭에서 POST /api/rag_search로 직접 질의하는 경우다.

LLM 호출은 실시간 스트림에서 분리했다. 대시보드로 나가는 MSE·상태 방송은 매 데이터 포인트마다 LLM 없이 처리하고, LLM이 붙는 정밀 분석은 run 에서 MSE 가 가장 컸던 시점 하나만 골라 나중에 돌린다.

SHAP 분석과 Knowledge Graph 조회는 ④ 이전에 끝난다. 두 결과를 문자열로 만들어 프롬프트에 넣고, SHAPAgent와 GraphRAGAgentV2를 asyncio.gather(..., return_exceptions=True)로 병렬 호출한다. Neo4j Aura 가 원격이라 간헐적으로 실패하는데, 그때 SHAP 쪽 결과까지 함께 버려지지 않게 하려는 것이다.

자동 경로와 수동 질의는 server._call_rag_v2() 하나를 공유한다. SHAP 결과(list)를 V2 가 받는 dict 로 바꾸는 것과 센서명을 KG 이름으로 맞추는 것은 rag_agent_v2 의 shap_list_to_dict() · SENSOR_ALIASES 가 맡는다. 모델은 TCP Top Pwr, KG 는 TCP Top Power 로 부르기 때문에 이 치환이 없으면 지문 매칭이 전부 빗나간다.

과금 스위치는 두 개다. OPENAI_ENABLED는 코드 기본값이 true(미설정 시 허용)지만 이 프로젝트 .env에는 false로 두고 있다. LLM_ANALYSIS_ENABLED는 코드 기본값과 .env가 모두 false다. 실시간 경로에서 LLM 이 호출되려면 둘 다 켜야 한다. ensure_openai_enabled()가 세 에이전트 __init__ 첫 줄에 있어, 꺼진 상태에서는 에이전트 객체 생성 단계에서 막힌다.

3. 현재 한계

  • 센서 지문만으로는 결함 등급을 가르지 못한다. KG 의 결함 21종 중 서로 다른 지문은 12종뿐이다. sensors_high = ["TCP Top Power"] 하나에 F01(TCP+50) · F05(TCP+10) · F10(TCP+30) · F21(TCP+20)이 걸려 스코어가 넷 다 1.00 동점이 된다. Stage 1 은 결함군까지만 좁히고, 그 안에서 어느 등급인지는 고르지 못한다. 실제 조회 결과로 확인했다.
  • OES · RFM 센서는 지문 매칭에 기여하지 않는다. KG 에는 MSS 센서 19개만 노드로 있고 OES 파장(364.33)이나 RFM 하모닉(S2P4)에 대응하는 노드가 없다. 정규화에서 원본 그대로 통과한 뒤 매칭에서 탈락한다. 218개 피처 중 지문에 쓰이는 것은 7개다.
  • LLM 출력의 내용을 자동으로 검증하지 않는다. 생성된 정비 가이드가 KG 에 실재하는 SOP 인지, 센서 근거와 모순되지 않는지 확인하는 단계가 없다. 현재는 SHAP 근거를 결과와 함께 보내 사람이 대조한다.
  • API 키 별칭 처리가 일부 파일에만 있다. .env 는 OPEN_AI_API_KEY 를 쓰는데 OPENAI_API_KEY 로 복사하는 코드가 shap_agent.py 와 server.py 에만 있다. rag_agent_v2.py 를 단독 실행하면 인증에 실패한다(서버 경로는 server.py 가 먼저 처리해 문제없다).
  • V1 이 검증 스크립트에 남아 있다. 실행 경로에서는 빠졌지만 validation/ 두 스크립트가 아직 GraphRAGAgent 를 부른다. 현행 KG 스키마와 맞지 않아 빈 결과를 낸다.
